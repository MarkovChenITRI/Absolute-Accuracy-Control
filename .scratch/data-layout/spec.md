## 目錄

```
data/
 ├ WR403/                                 機型（R1）
 │  ├ 上台_A軸/                           軸：這一軸自己的工程與實驗（R2、R14）
 │  │  ├ 工程/                            MR Configurator2 工程，這一軸全部實驗共用（R3）
 │  │  └ 實驗紀錄/                        （R9）
 │  │     ├ A01_伺服調機/                 一組實驗（R4）
 │  │     │  ├ 紀錄.json                  mod 讀寫的唯一紀錄檔（R10、R12）
 │  │     │  └ 參數/                      每一個實驗結果一份參數檔（R8）
 │  │     └ B01_<名稱>/
 │  │        ├ 紀錄.json
 │  │        ├ 參數/
 │  │        └ 採樣/                      MS1811 匯出的 CSV（R11）
 │  └ 上台_B軸/  下台_A軸/  下台_B軸/
 └ WR503/                                 五軸，結構相同
```

- 類型資料夾用使用者定義的三種資料命名：工程、參數、採樣。`工程/` 在軸這一層，`參數/`、`採樣/` 在實驗組這一層。不用物理量或儀器型號當資料夾名稱。
- 只建這組實驗用得到的類型。依標準作業流程調機的結果是參數，所以只有 `參數/`。
- MS1811 量的是全部軸的合成，CSV 存在這一軸實驗的 `採樣/`，但不拿來判定這一軸。
- 資料夾內的檔名一律用軟體存檔時給的名稱。每個檔案在什麼條件下取得，記在 `紀錄.json`，不寫進檔名（R10）。
- `工程/` 由 MR Configurator2 產生與管理，不手動修改。每一軸的 `工程/` 是一個獨立的 MR Configurator2 工作區；換軸時開另一軸的 `工程/`。
- 圖表波形不存檔（R13）。
- `data/` 放在專案根目錄，與 `docs/` 一樣不進版本控制。

| 對象 | 規則 | 例子 |
|---|---|---|
| 機型 | 機型代號 | `WR403` |
| 軸 | 與 `mods/tune/procedures/<機型>.json` 的 `axes` 同名 | `上台_A軸` |

## 紀錄.json

每組實驗一份，mod 只讀寫這一個檔。

```json
{
  "procedure": "wr403",
  "items": {
    "inertia.pb06": { "status": "pass", "step": 9, "value": "PB06 = 3.21", "param": "參數/<存檔時給的名稱>" },
    "gain.pb09": { "status": "waiting", "step": 4 }
  },
  "log": [
    { "time": "2026-10-14T10:31:40+08:00", "item": 1, "step": 8, "by": "AI", "read": "PB06 平均 3.21，變異係數 1.8%" },
    { "time": "2026-10-14T10:33:02+08:00", "item": 1, "step": 9, "by": "AI", "file": "參數/<存檔時給的名稱>" }
  ]
}
```

每一個項次判定完（通過或未通過），AI 在照「合格時寫入」或「不合格時寫入」寫進驅動器之後，從驅動器讀出全部參數存成一份參數檔，檔名寫進那一項的 `param`（R8）。重做一個項次會產生新的結果與新的參數檔，`param` 指向最新那一份；舊檔留在 `參數/`，由 `log` 追溯。

有採樣資料的實驗，`log` 裡每一個 CSV 一筆，寫明它是在什麼參數下量的：

```json
{ "time": "2026-10-14T14:20:05+08:00", "step": 3, "by": "工程師", "file": "採樣/<MS1811 匯出的檔名>.csv",
  "params": { "layer": 25, "wafer": true } }
```

CSV 的檔名照 MS1811 匯出時的名稱，不修改；CSV 與參數的對應只記在這裡。

- `procedure`：照哪一份程序做。
- `items`：各項次的狀態、做到第幾步、判定數值。取代舊版進度檔的 `runs`。
- `log`：過程紀錄，一筆一個動作。畫面讀到的數值寫在 `read`，存下的檔案寫在 `file`。

`mods/tune/.tune/session.json` 只留目前選擇：機型、軸、實驗組。mod 用它找出要讀哪一個 `紀錄.json`。

## mod 怎麼讀

| 畫面 | 讀什麼 | 什麼時候讀 |
|---|---|---|
| 調機總覽、標準作業流程 | 目前那組實驗 `紀錄.json` 的 `items` | 每 3 秒，內容有變才重畫，與現在相同 |
| TAB3 實驗紀錄 | 這一軸 `工程/` 裡有沒有 `Project.mr2`；`實驗紀錄/` 底下的任務清單；所選任務 `紀錄.json` 的 `params` | 每 3 秒，與調機總覽相同 |

## /tune 開始時自動建好工程（R15）

`/tune <機型>` 讀程序定義的 `axes`，逐軸檢查 `data/<機型>/<軸>/工程/` 底下有沒有 `Project.mr2`。缺的那一軸，由 AI 在 MR Configurator2 建立工程，工作區位置設在那一軸的 `工程/`，再建好 `實驗紀錄/<組>/紀錄.json` 與 `參數/`。全部軸都有工程後才回報完成。

## TAB3 實驗紀錄

機型與軸完全依調機總覽目前選中的，分頁上不另外顯示（R17）。

**沒有工程時**，整個分頁只顯示一段操作引導與「重試」按鈕，不顯示任務與參數表：

> 沒有找到工程。MR Configurator2：**工程** > **新建**，工作區選「data\WR403\上台_A軸\工程」，工程名稱填「上台_A軸」，點擊**確定**。
>
> [重試]

「重試」只為這一軸重新建立工程（R16）。

**有工程時**：

| 區塊 | 內容 |
|---|---|
| 任務 | 下拉選單，選項是這一軸 `實驗紀錄/` 底下的每一組實驗，最後一項是「＋新增任務」（R18）。選其他任務就切過去；選「＋新增任務」出現名稱輸入框，按 Enter 建立 `A<最大號+1>_<名稱>/紀錄.json`，程序沿用目前任務的，建好切到新任務；留空按 Enter 取消 |
| 參數表 | 每一列是一次參數存檔（`紀錄.json` 的 `params` 的鍵），每一欄是程序定義 `params` 列出的參數中文名稱，順序照 README 參數表的調整順序；只顯示有值的欄。每一格都是輸入框：AI 存檔時讀得到的值先代填，人改了就寫回 `紀錄.json`，不需要按儲存。還沒有存檔時顯示「還沒有參數存檔」 |

```json
"params": { "參數/xxx_1.prm2": { "負載慣量比": "3.21", "速度控制增益": "120" } }
```

- 切換任務後，調機總覽的驗收項目、標準作業流程分頁都改成那個任務的：程序取自那組實驗 `紀錄.json` 的 `procedure`，狀態取自它的 `items`。
- 缺參數檔的項次，判定不算數：調機總覽上那一項顯示「存參數檔」，不打勾；這一軸也不算調完。
- 採樣檔只登記在 `log`，分頁上不檢核。
